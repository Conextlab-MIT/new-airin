[Coolify](https://coolify.io) is a self-hosted PaaS that manages Docker deployments, reverse proxy, and SSL for you. Airin runs on it via the **Docker Compose** resource type — no upstream template approval needed.

## Deploy

1. In your Coolify project, create a new resource → **Docker Compose Empty**.
2. Paste the compose file below. If you use the repository's `docker-compose.yaml`, remove its `env_file` lines.
3. Set `AIRIN_SECRETS_KEY` in Coolify's Environment Variables before deployment.
4. Click **Deploy**.

```yaml
services:
  airin:
    image: ghcr.io/ahmadrosid/airin:latest
    ports:
      - "4310:4310"
    environment:
      - AIRIN_CONFIG_DIR=/airin/data
      # Optional: skip the browser setup wizard on first boot.
      # All three must be set together or none at all.
      # - AIRIN_SEED_ADMIN_EMAIL=admin@example.com
      # - AIRIN_SEED_ADMIN_NAME=Admin
      # - AIRIN_SEED_ADMIN_PASSWORD=changeme123
      # Optional: public URL for OAuth callbacks and shared links.
      # - AIRIN_WEB_PUBLIC_URL=https://airin.example.com
    volumes:
      - airin-data:/airin/data
    restart: unless-stopped

volumes:
  airin-data:
```

On first run, open the assigned domain and complete the setup wizard. To skip the wizard, uncomment the `AIRIN_SEED_*` variables — all three are required together.

## Environment variables

Set these in the Coolify UI under **Environment Variables**:

| Variable | Required | Purpose |
|---|---|---|
| `AIRIN_SECRETS_KEY` | Yes for Settings keys | A random 32-byte key in base64; keep it separate from the data volume and backups |
| `AIRIN_SEED_ADMIN_EMAIL` | Together with the other two | Admin email — skips setup wizard |
| `AIRIN_SEED_ADMIN_NAME` | Together with the other two | Admin display name |
| `AIRIN_SEED_ADMIN_PASSWORD` | Together with the other two | Admin password (min 8 chars) |
| `AIRIN_WEB_PUBLIC_URL` | Recommended | Public URL Coolify assigns, e.g. `https://airin.example.com` |

Set `AIRIN_WEB_PUBLIC_URL` to the domain Coolify routes to your service. Airin uses it for OAuth callbacks and shared links.
Generate `AIRIN_SECRETS_KEY` with `openssl rand -base64 32` and back it up outside Coolify's Airin volume.

## SSE and reverse proxy

Airin uses Server-Sent Events for streaming responses. Coolify's default Traefik proxy handles SSE correctly with no extra config.

Traefik also sends `X-Forwarded-Host` and `X-Forwarded-Proto` on every request. Set `AIRIN_TRUST_PROXY=true` in the service environment so Airin uses them for OAuth callbacks, passkey sign-in, and first-run setup when `AIRIN_WEB_PUBLIC_URL` is not set. Without the flag or the public URL, a caller-named remote origin is refused and connect flows fail closed.

If you use a custom Nginx proxy in front of Coolify, disable buffering for the Airin location:

```nginx
proxy_buffering off;
proxy_set_header X-Accel-Buffering no;
```

## Healthcheck

The container ships a built-in healthcheck on `GET /health`. Coolify picks this up automatically — no extra configuration needed.
